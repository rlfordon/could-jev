# Sweep 2026-10-15

This sweep was run early because of a big release. **Jev 1.14.0 came out on about 2026-10-14**, with three experimental "danger zone" features: **image input**, a new **Box** question type that locates a region of an image, and **long context** (262k tokens). Price is unchanged.

docs.typesafe.ai and typesafe.ai weren't reachable from the sweep environment. The official facts below come from the SDK packages themselves (PyPI `typesafe-sdk` 0.7.5, npm `@typesafe-ai/sdk` 0.7.0, and `@ai-sdk/typesafe-ai` 3.0.19, all diffed against the versions at the last sweep), the GitHub release notes, and search-result summaries of TypeSafe's 1.14 announcement. Items marked *(unconfirmed)* should be re-checked against docs.typesafe.ai/images and /models next sweep.

## Official changes

**Model:**
- `jev-1.14.0` was released behind `jev-preview` (announcement: typesafe.ai/blog/jev-1-14, "Jev: For the builders AND dreamers"). `jev-latest` ("latest stable") is due to move from 1.13.0 to 1.14 about a week later, so around 10-21.
- Deprecation notice is 60 days for 1.13.0 and 30 days for 1.14.0.
- The `@ai-sdk/typesafe-ai` model IDs are now `jev-1.13.0`, `jev-1.14.0`, `jev-latest` and `jev-preview`.

**Danger zone.** These are opt-in by request header. TypeSafe says there is "still way too much jaggedness" to vouch for them in production.
- **Images** (`TypeSafe-Danger-Zone-Images: true`; works on 1.13 and 1.14):
  - PNG or JPEG only. Sent as multipart, with an `assets` map of placeholder references.
  - An image can go in `state`, `instructions` or `criteria`. Each mention of the reference inserts the image again.
  - Billed as input tokens: about 4,000 to 5,200 tokens for a ~1.5k px photo (community measurements).
  - Limits *(unconfirmed)*: 16 MiB per image and 256 to 1,568 px per side; 400 if too small, 413 if too large; EXIF orientation ignored.
  - The schema says "Image assets require a vision-language model."
  - The Vercel AI Gateway rejects files.
- **Box question** (1.14 only; 1.13 returns 400):
  - Returns `top`, `bottom`, `left` and `right` as fractions of the image size, each the expected position of that edge, plus a `confidence` that can be null.
  - There's one box per question and no "not present" answer.
- **Long context** (`TypeSafe-Danger-Zone-Long-Context: true`; 1.13 and 1.14):
  - Raises both the per-request and per-question limits to 262k tokens, at the same price.
  - TypeSafe calls it slower and less accurate.

**SDKs:**
- Python `typesafe-sdk` 0.7.3 and 0.7.4 (10-09) fixed bugs and changed keepalive. 0.7.5 (10-14) added `Image` (from a path, bytes, base64 or PIL), `Box`, `response.boxes` and `attach_assets`, and turned zstd request compression on by default. It added the extras `pil` and `zstd`. A Noul can now omit `instructions` if `criteria` describes an outcome.
  - The Python SDK does **not** add the images header itself. The JS SDK docs and the Vercel provider do.
- JS `@typesafe-ai/sdk` 0.7.0 (10-14) added `image()`, `withAssets`, `box()` and zstd compression. It now requires Node 22.
- `@ai-sdk/typesafe-ai` 3.0.16 to 3.0.19 added image file parts, `longContext` and `TYPESAFE_AI_BASE_URL`. It has no Box question.

**Unchanged:** price ($0.042 per million input tokens; output is free), rate limits, Choice, Score and Noul limits, and access routes. No gateway lists 1.14 yet.

**Not reached:** the 1.14 jaggedness page, the official image limits page, and TypeSafe's internal image benchmarks. One outlet mentions published benchmarks against open-weight models, with images less reliable than text.

**What might no longer hold on 1.14:** all the cookbook and community numbers (measured on 1.12 and 1.13), the run-to-run variance figures, and any thresholds users tuned on `jev-latest`. The factsheet now tells users to pin `jev-1.13.0` before `jev-latest` moves.

## New patterns

| # | Pattern | Evidence |
|---|---|---|
| 32 | **Locate, crop, confirm** (images): a Box or grid proposes a region, code crops it, a neutral Noul confirms | jev-box-study: 97–98% of planted text errors caught; the confirm step cut real-photo false flags from 4/26 to 0/26; about $0.02 per image. Small hand-built sets. |

Also added: a new section **K. Images (experimental)**, an "Images" lever in the intro, an image line under Fit signals, and an exception in the "can only point at enumerated options" line.

## Variants / domains folded in

- **#7 Beam descent:** a grid-of-crops descent over images (axe-decision-control: grid about $0.005 a run vs. Box about $0.003; demo).
- **#15 Heat map:** fan the same Noul out over image tiles.
- **#18 Pairwise:** image vs. image, or image vs. claim. Example: a seller's upload vs. the catalog photo (SDK docs), and video-image-tagger (demo).
- **#29 Legal-move picker:** a screenshot with numbered elements, then a Choice (jev-phone, about 0.7 s per step; OpenComputerUse, with Box as a fallback).
- **Not a Jev job:** pixel-exact geometry, plus a privacy option: run OCR locally and send only text (omarchy-laser).

## Rules changed

- **Window first** now covers images: crop first. A paragraph crop scored 0.90 vs. 0.60 for the whole page. This is a clause in an existing rule, consistent with jaggedness item 3.
- **New hunch, "Loaded words may tilt the answer":** words like "AI" or "hallucination" in the question pushed 7 of 8 real photos to yes. One source only.
- **New hunch, "On images, Jev may read meaning, not exact layout":** table misalignments didn't separate from clean tables, and a raw Box was the weakest way to locate. Two sources (jev-box-study, plus an anecdotal Box test).

## Reported failures / limits

**Box:**
- It always returns a box.
- It returned zero-width boxes, the same region again after masking, and one giant box for "find anything".
- In an anecdotal test, a raw Box located 20 of 36 targets, vs. 30 of 36 for four per-edge questions.
- In an iOS demo, it stayed under a 0.90 presence gate.

**Images:**
- A 278 px crop was rejected (minimum about 280).
- Run-to-run spread was 0.57 to 0.67 on the same crop.
- Through the Vercel Gateway, Jev said the image "wasn't visible", and `jev-preview` returned 404 (agent-native-images). This is consistent with the Gateway rejecting files.
- Color values: hex and RGB values still do worse than names (universal-theme-extension), consistent with jaggedness item 2.

**Text:**
- Guardrail test (1,000 items): Jev caught 78.2% of adversarial rewrites vs. 94.0% for Haiku 4.5. Detection was 91.9% vs. 96.6%, with fewer false positives (9.6% vs. 14.1%), about 6x faster and about 60x cheaper. Source: rahulbansalc6414/jev-as-a-guardrail, read via a digest; the digest flags an inconsistent miss count.
- 1.14 benchmark (etsabary, 1,136 questions): multi-step sequential procedures stayed very weak, 6 of 42.

## Interesting but unproven (report only)

- **1.14 vs. 1.13** (etsabary): 82.0% vs. 80.1%, with the largest gain on verbal spatial tracking (55.8% to 74.4%). At confidence 0.9 or higher, 99.5% accuracy on 57.8% of items. p50 latency 148 ms. One benchmark only.
- **stern9/jev-bench** (72 items): Jev 94.4% vs. Haiku 5.5 95.8% vs. Opus 5.5 97.2%, at p50 latencies of 171 ms, 1.44 s and 2.12 s. ECE 0.025. The calibration figure is good, but it doesn't outweigh the earlier poor-calibration reports on a set this small.
- **JevGPT** (arXiv 2610.18272, via a digest): GPT-5.5 plus Jev scored 90.48% on BrowseComp-Plus; replacing Jev with GPT-5.5 cost about 100x more.
- **Image benchmarks under way:** the ImageJevBench Box track (300 items, scored by IoU and ECE, no results yet), and a stoplight-grid captcha eval with Jev 1.14 still pending.
- **Speed claims on images:** about 100 ms (HN), under 1 s, about 0.3 s (gspro-commentator), and about 200 ms per step (flick). None has a matching accuracy number.
- **TechTimes funding report ($870M):** unverified and irrelevant to the skill.
