# Sweep 2026-10-15

This sweep was run early because of a big release. **Jev 1.14.0 came out on 2026-10-14**, with three experimental "danger zone" features: **image input**, a new **Box** question type that locates a region of an image, and **long context** (262k tokens). Price is unchanged.

It ran in two passes on the same day. The first pass couldn't reach docs.typesafe.ai, typesafe.ai, Hacker News, Reddit, X, Bluesky or most blogs, so it worked from the SDK packages, GitHub and search summaries. The second pass reached the official docs and blog, HN (via Algolia), Bluesky and the blogs. It confirmed or corrected the first pass's official facts and added the community reports below. Reddit and X still weren't reachable.

## Corrections to the first pass

- **OpenRouter does list 1.14.** `typesafe/jev-1.14` was created 2026-10-14 (262k context, text and image input) and was already serving traffic. Only Vercel lacks it.
- **The "20 vs. 30 of 36" Box numbers are TypeSafe's own test, not an anecdote, and they measure *checking* a box, not locating.** On 36 painting crops, one Noul per edge caught 30 cut-offs, one "is all of it inside?" Noul caught 26, and an outline drawn on the full image caught 20. The factsheet line and the "reads meaning, not layout" hunch were reworded.
- **Box edges aren't described as "expected" positions.** The docs just say fractions from 0 to 1, with (0,0) top-left. Confidence is 0 to 1; only the JS type allows `null`.
- **The JS SDK doesn't add the images header either.** Only the Vercel AI SDK provider does. Python passes it with `TypeSafeClient(headers=...)`, not `default_headers`.
- **"Any request with an image runs in long-context mode" (one guide) is not supported.** The docs say images count against the normal context limit. Dropped.
- **Confirmed:** the deprecation notice periods (TypeSafe "intend[s] to give 60 days warning" for 1.13.0, 30 days for 1.14.0) and `jev-latest` moving "in a week". Both appear only in the blog post. The ~10-21 date is our inference.
- **Confirmed:** "still way too much jaggedness for us to vouch for these for production use cases".
- **Confirmed:** "Vercel AI Gateway rejects files"; one box per question with no "not present" answer; the Python SDK doesn't add the images header.

## Official changes

**Model:**
- `jev-1.14.0` was released behind `jev-preview` (which can also carry unofficial builds). Announcement: typesafe.ai/blog/jev-1-14, "Jev: For the builders AND dreamers". `jev-latest` still points to 1.13.0; the blog says it moves "in a week", with no date.
- Deprecation (blog only, stated as an intention): 60 days' warning for 1.13.0, 30 days for 1.14.0. A formal deprecation policy is promised but not yet published.
- The docs have no product changelog and no 1.14 jaggedness page. The 1.13 list (reviewed 10-02) is still the only official one, with no image items.
- The blog says 1.13.0 was already multimodal, which is why images work on both versions.

**Danger zone.** Opt-in by request header. The docs label it "Dreamer-ready", and the blog says there is "still way too much jaggedness for us to vouch for these for production use cases". There are no official accuracy numbers, only "internal best guesses". "All models (Jev included) perform worse on multimodality over pure text", and breaking questions into their simplest parts "helps a lot".
- **Images** (`TypeSafe-Danger-Zone-Images: true`; 1.13 and 1.14), now confirmed from docs.typesafe.ai/images:
  - Still PNG or JPEG only. Sent as multipart parts (recommended) or base64, with an `assets` map of placeholder references.
  - Images can go in `state`, `instructions`, `criteria`, and inside Choice options, Score levels and Noul definitions. References are plain-text matches, object keys aren't replaced, and an unreferenced asset returns 400. Each use of a reference inserts the image again.
  - Limits: 16 MiB per file; 256 to 1,568 px per side and 78,400 to 2,458,624 total pixels; 32 MiB per request, after expansion. Oversized or undersized images are rejected, not resized: 400 or 413. Metadata is stripped and EXIF orientation isn't applied. One bad image fails the whole request.
  - Billed as input tokens and counted against the normal context limit. No official estimator yet. No separate rate limits.
- **Box question** (1.14 only; 1.13 returns 400), from docs.typesafe.ai/primitives/box:
  - `instructions` only, which can be a description. Returns `top`, `bottom`, `left` and `right` as fractions with (0,0) at top-left, plus `confidence`, 0 to 1.
  - One box per question and no "not found" answer: pair it with a presence Noul. For several objects, describe the one you want or add a Choice none/one/several.
  - Small targets in large images get missed, so pick a tile with a Choice first. Check boxes with one Noul per edge on the crop (see Corrections). No recommended threshold.
- **Long context** (`TypeSafe-Danger-Zone-Long-Context: true`; 1.13 and 1.14): 262k tokens for both limits at the same price. Slower and less accurate; TypeSafe "strongly recommend[s] limiting context length".

**SDKs** (nothing newer than the first pass found):
- Python `typesafe-sdk` 0.7.3 and 0.7.4 (10-09) fixed bugs and changed keepalive. 0.7.5 (10-14) added `Image`, `Box`, `response.boxes` and `attach_assets`, and turned zstd compression on by default. It added the extras `pil` and `zstd`. A Noul can now omit `instructions` if `criteria` describes an outcome.
- JS `@typesafe-ai/sdk` 0.7.0 (10-14) added `image()`, `withAssets`, `box()` and zstd compression. It requires Node 22. It doesn't add the images header.
- `@ai-sdk/typesafe-ai` 3.0.16 to 3.0.19 added image file parts (sending the header automatically), `providerOptions.typesafe.reference`, an opt-in `longContext`, model IDs including `jev-1.14.0` and `jev-preview`, and `TYPESAFE_AI_BASE_URL`. Box is listed under "Future work".

**Access:** OpenRouter lists `typesafe/jev-1.14` (262k context, text and image input). Vercel AI Gateway still lists only `typesafe-ai/jev`, text-only with 32k context, and still rejects files. Pydantic AI Gateway is unchanged.

**Unchanged:** price ($0.042 per million input tokens; output is free), the 64k/32k default budget, 255 Choice options, 2 to 10 Score levels, and the 32 MiB body limit. The docs give no rate-limit figures.

**What might no longer hold on 1.14:** all the cookbook and community numbers (measured on 1.12 and 1.13), the run-to-run variance figures, and any thresholds users tuned on `jev-latest`. One 30-image test found 1.14 *stricter* than 1.13 (correct matches at 0.5 or above: 15 of 30 vs. 23 of 30). The factsheet tells users to pin `jev-1.13.0` before `jev-latest` moves.

## Variants / domains folded in

- **#3 Funnel:** SREGym incident diagnosis, 80 of 105 passed (76% vs. 78% for an LLM agent), about 7x faster, $0.15 total (2026-10-06).
- **#7 Beam descent:** a grid-of-crops descent over images (axe-decision-control: grid about $0.005 a run vs. Box about $0.003; demo).
- **#10 Uncertainty spotlight, on images:** MaceTenth/jev-vision-benchmarks, catalog-photo moderation with five Nouls per photo on 1.14. Sending the 0.3–0.7 band to a person put 4 of 294 answers in review, including both errors. It caught 7 of 8 problems with 1 false alarm in 286, at a median 376 ms and $123 per million photos. gpt-5.5 caught 8 of 8 at $7,797 per million; Rekognition and omni-moderation flagged nothing. Caveats: 60 photos, Claude-written labels, 8 positives.
- **#14 Locator:** Sayora page routing. The right page came first 88% of the time vs. 70% for embeddings (86% for a frontier LLM), and "none of these" was right 95% of the time vs. 23%. $0.45 for 1,449 requests (2026-10-12/13).
- **#15 Heat map:** fan the same Noul out over image tiles.
- **#18 Pairwise:**
  - Image vs. image, or image vs. claim: a seller's upload vs. the catalog photo (SDK docs), and video-image-tagger (demo).
  - Image vs. headline (Thorsten Meyer, 30 images, read via a 1023jack.com republication): AUC 0.91 on 1.14 vs. 0.89 on 1.13; all 60 off-topic pairings rejected; about 0.36 s and 1,600 tokens per 1024×576 image. Look-alike stock photos couldn't be told apart, and a mesh Wi-Fi photo was called a "Wi-Fi 7 router" at 0.60.
- **#29 Legal-move picker:** a screenshot with numbered elements, then a Choice (jev-phone, about 0.7 s per step; OpenComputerUse, with Box as a fallback).
- **Not a Jev job:** pixel-exact geometry, plus a privacy option: run OCR locally and send only text (omarchy-laser).

## Rules changed

- **Window first** now covers images: crop first. A paragraph crop scored 0.90 vs. 0.60 for the whole page, and TypeSafe's Box guidance agrees (tile first, re-ask on a tighter crop).
- **Request shape changes answers:** added gc.ai's drop from 96% to 72% when similar items were packed into one array.
- **New hunch, "Loaded words may tilt the answer":** words like "AI" or "hallucination" pushed 7 of 8 real photos to yes. The second pass added a text report (gc.ai: "limited liability" flagged ordinary refund clauses, and narrower wording halved false alarms). It stays a hunch: no direct replication of the image result.
- **New hunch, "On images, Jev may read meaning, not exact layout":** table misalignments didn't separate from clean tables, look-alike stock photos weren't separable (Meyer), and judging a box from its outline on the full image caught the fewest cut-offs in TypeSafe's test.

## Reported failures / limits

**Box:**
- It always returns a box, even for an absent target (a missing bicycle got one at confidence 0.03, Meyer; also two Bluesky reports). TypeSafe's docs confirm this.
- It returned zero-width boxes, the same region again after masking, and one giant box for "find anything" (jev-box-study).
- In an iOS demo, it stayed under a 0.90 presence gate.

**Images:**
- A 278 px crop was rejected. The official total-pixel floor (78,400) explains it.
- Run-to-run spread was 0.57 to 0.67 on the same crop.
- Through the Vercel Gateway, Jev said the image "wasn't visible", and `jev-preview` returned 404 (agent-native-images). This is consistent with the Gateway rejecting files.
- Color values: hex and RGB values still do worse than names (universal-theme-extension), consistent with jaggedness item 2.
- 1.14 rejected more correct image–headline matches than 1.13 at a 0.5 cut (Meyer).

**Text:**
- **Vals AI LegalBench (2026-10-06):** last of 12 systems on class-balanced accuracy (0.730). It answered "Yes" to all 33 items of contract_nli_permissible_copy. ECE was 0.108 on LegalBench, the worst of 12, but 0.011 on claim verification, the best.
- **gc.ai hackathon (2026-10-06):** weekday of a date right about 20% of the time. Packing similar items into one array dropped accuracy from 96% to 72%. With no "none" option it picked a wrong date at 0.92; with no context it still broke ties at 0.81–0.89; a broad "is this test useless?" question scored AUC 0.54.
- **Judge study (deeplearningguy, 2026-10-06):** 48.2% accuracy vs. 45.8% for Haiku. Jev's confidence was further from its accuracy, and no model's confidence flagged contested items.
- **IT-ticket routing (SFEIR, via the HF forums):** department 41% and priority 57%, vs. 62% and 72% for a fine-tuned local model.
- **Prompt injection:** Respan saw injected text flip a confident Travel label to Shopping at 0.82. An NTU paper's adaptive attacks raised success from 1.8% to 3.5%. Check Point reported breaking every configuration at about 50 cents per break. The Register ran a headline (article not reached).
- **Guardrail test (1,000 items):** Jev caught 78.2% of adversarial rewrites vs. 94.0% for Haiku 4.5. Detection was 91.9% vs. 96.6%, with fewer false positives (9.6% vs. 14.1%), about 6x faster and about 60x cheaper. Source: rahulbansalc6414/jev-as-a-guardrail, read via a digest; the digest flags an inconsistent miss count.
- **1.14 benchmark (etsabary, 1,136 questions):** multi-step sequential procedures stayed very weak, 6 of 42.
- **HN:** one commenter found the Decisions API "worse in all dimensions"; another's local 4B model came within 1 point of Jev on a private benchmark.

## Interesting but unproven (report only)

- **1.14 vs. 1.13** (etsabary): 82.0% vs. 80.1%, with the largest gain on verbal spatial tracking (55.8% to 74.4%). At confidence 0.9 or higher, 99.5% accuracy on 57.8% of items. p50 latency 148 ms. One benchmark only.
- **stern9/jev-bench** (72 items): Jev 94.4% vs. Haiku 5.5 95.8% vs. Opus 5.5 97.2%, at p50 latencies of 171 ms, 1.44 s and 2.12 s. ECE 0.025. Too small to outweigh the poor-calibration reports.
- **JevGPT** (arXiv 2610.18272, via a digest): GPT-5.5 plus Jev scored 90.48% on BrowseComp-Plus; replacing Jev with GPT-5.5 cost about 100x more.
- **Text as an image, then Box for spans** (aleksiy123, HN 1.14 thread): a workaround for Jev having no span type. Idea only, but a genuinely new shape; watch for a test.
- **Yes/no beats grades for code review** (labrodev, Bluesky): grading code gave nothing useful, but yes/no questions caught 29 of 30 planted bugs in 80 s for $0.56. One post, planted bugs; it sits against earlier reports that code review as the only reviewer flopped.
- **"Bag of Decisions" reranker** (HN, ahevenor, 10-12): nDCG@10 0.768 at $0.60 per 1k queries vs. 0.756 for Opus 5 at $94.68. Consistent with the documented reranking pattern (#18).
- **Smaller items:** James Carr's code-search funnel (629 calls for $0.089); an effort router built on Jev's difficulty estimate (polski-g, HN); hot-or-not-jev, a Choice across a user's photos (demo only).
- **Image benchmarks under way:** the ImageJevBench Box track (300 items, scored by IoU and ECE, no results yet), and a stoplight-grid captcha eval with Jev 1.14 still pending. The MaceTenth repo has untested title-vs-photo and label-reading (vs. Tesseract) scripts.
- **Speed claims on images:** about 100 ms (HN), under 1 s, about 0.3 s (gspro-commentator), and about 200 ms per step (flick). None has a matching accuracy number. The measured ones are 376 ms median (MaceTenth) and about 0.36 s (Meyer).
- **TechTimes funding report ($870M):** unverified and irrelevant to the skill.
